# Repository leads for an exponent-improvement project

Audit date: 2026-10-12 (America/Los_Angeles). Scope: the six public repository leads in the prior omega discussion handoff. The objective of this project is a strict arithmetic-exponent improvement below 9/4; additional field coverage of the same exponent is relevant infrastructure, not that objective.

This is a source and artifact-metadata audit. Repository pages, README files, licenses, selected validation/release records, and AlphaTensor array headers were read. No upstream program, notebook, search, test suite, Lean build, or kernel replay was executed. Consequently, upstream reports of verification remain attributed reports. This audit neither establishes a new bound nor certifies the current worldwide rank record for any format.

## What the leads actually supply

### Numerical discovery followed by exact reconstruction

**switzerlandomics/ai-fast_mm_search.** Dylan Lawless's `fast_mm` seeks finite bilinear decompositions using random restarts, numerical optimization, exact rational reconstruction, and coefficient-level checking. Its current README reports rediscovering a 2-by-2, seven-product integer identity at seed 581. It explicitly treats this as validation of a known result, not a new rank bound; recursive exponent is `log_2(7)`, above 9/4. The verifier's advertised coefficient domain is rational, so algebraic/complex searches require a domain extension. Useful ideas are durable restart bookkeeping and strict separation of numerical candidates, exact identities, unsuccessful bounded searches, and execution errors. The README's verification claim was not replayed here. [Pinned README](https://github.com/switzerlandomics/ai-fast_mm_search/blob/17a66cd51798fc0985d5953bad5d3d93987fa99d/README.md), [citation metadata](https://github.com/switzerlandomics/ai-fast_mm_search/blob/17a66cd51798fc0985d5953bad5d3d93987fa99d/CITATION.cff).

The repository contains multiple historical validation scopes: `VALIDATION.md` describes an October 7 snapshot with 25 tests and numerical candidates that failed exactification; `PACKAGE_CONTENTS.txt` reports 33 packaging tests. Neither count should be relabeled as a current-head independent pass or used to contradict the later reported seed-581 result. [Validation record](https://github.com/switzerlandomics/ai-fast_mm_search/blob/17a66cd51798fc0985d5953bad5d3d93987fa99d/VALIDATION.md), [packaging record](https://github.com/switzerlandomics/ai-fast_mm_search/blob/17a66cd51798fc0985d5953bad5d3d93987fa99d/PACKAGE_CONTENTS.txt).

**nickedfrc/matrix-multiplication-paper-reproduction.** An educational implementation of finite tensor constructions, exact algebraic certificates, FFT projections, and matrix multiplication benchmarks. It explicitly reports no certificate attaining the 9/4 result. Its exhaustive search enumerates number-field descriptions and coefficient arrays, using exact quotient arithmetic and a fair schedule. Eventual success is conditional on the cited existence theorem and unlimited resources; the admission threshold includes positive exponent slack. Its FFT packing costs `O(n^3 log n)` time and `O(n^3)` storage for square inputs. Useful components are the distinction between convolution factors and a matrix-tensor decomposition, exact algebraic arithmetic, and corrupted-certificate controls. The reported tests are upstream reports, not our replay. [Pinned README](https://github.com/nickedfrc/matrix-multiplication-paper-reproduction/blob/f9359e31619e7b62f55d562b16d827fee687be2b/README.md), [NOTICE and mathematical provenance](https://github.com/nickedfrc/matrix-multiplication-paper-reproduction/blob/f9359e31619e7b62f55d562b16d827fee687be2b/NOTICE).

### Small-format schemes and transformations

**dronperminov/FastMatrixMultiplication.** Andrew Perminov's catalogue and tooling target formats with each dimension at most 16, emphasizing ternary integer coefficients. The README reports, for example, a 70-product `2×4×11` scheme and a 102-product `3×5×9` scheme. These are attributed finite-format claims; optimality and current-record status were not independently audited. Methods include meta flip graphs, SAT neighborhoods of binary schemes, binary-to-ternary lifting, and addition reduction. Scheme records distinguish `Z2`, `ZT`, `Z`, and `Q`; the `z2` flag alone is insufficient to document rational denominator restrictions. Both complete factors and reduced addition schedules are described. The factors use a transposed output convention. Useful material is a diverse certificate corpus and local transformations, with separate checks for rank, coefficient domain, and additive cost. [Pinned README](https://github.com/dronperminov/FastMatrixMultiplication/blob/7e3ac35ca92cb30d568519ea63d7a1accad2c908/README.md).

The catalogue incorporates contributions from other sources; provenance is per scheme, not just per repository. Its changelog distinguishes imported schemes, rank improvements, rediscoveries over a different coefficient set, and addition reductions. Those are different accomplishments. [Pinned changelog](https://github.com/dronperminov/FastMatrixMultiplication/blob/7e3ac35ca92cb30d568519ea63d7a1accad2c908/CHANGELOG.md).

**google-deepmind/alphatensor.** The repository accompanying Fawzi et al., *Discovering faster matrix multiplication algorithms with reinforcement learning*, Nature 610 (2022), DOI `10.1038/s41586-022-05172-4`, supplies discovered factorizations, recombination code, nonequivalence material, and hardware benchmarking. Its documented four-directory release is not a complete training-system reproduction. Standard arithmetic and characteristic-two factors are separate datasets. Recombination and equivalent-representation diversity are useful search ideas; hardware speed and asymptotic exponent remain different objectives. [Pinned README](https://github.com/google-deepmind/alphatensor/blob/1949163da3bef7e3eb268a3ac015fd1c2dbfc767/README.md).

Read-only inspection of the released NPZ member headers found `4,4,4.npy` of shape `(3,16,47)` in the F2 archive and `(3,16,49)` in the standard-arithmetic archive. These are stored factor counts, **not independently verified ranks or optimality proofs**. The notebook states that its tensors output `(AB)^T`; importers must account for that indexing. No NumPy pickle or upstream notebook was executed. [F2 factors](https://github.com/google-deepmind/alphatensor/blob/1949163da3bef7e3eb268a3ac015fd1c2dbfc767/algorithms/factorizations_f2.npz), [standard factors](https://github.com/google-deepmind/alphatensor/blob/1949163da3bef7e3eb268a3ac015fd1c2dbfc767/algorithms/factorizations_r.npz), [format notebook](https://github.com/google-deepmind/alphatensor/blob/1949163da3bef7e3eb268a3ac015fd1c2dbfc767/algorithms/explore_factorizations.ipynb).

Observed archive SHA-256 values: F2 `70f09f349d8d2874ef0e0e089459c7320f5aa3eef277df5ffa67f573709db2da`; standard `4d59571a2537a9472e8229176d5ebe2925f3e041ad403c095b41853026caec33`. The Nature page redirected to an inaccessible identity-provider page in this audit, so its full text was not reviewed.

### Formalization of the same bound over more fields

**jzuiddam/omega-nine-quarters-all-fields.** Jeroen Zuiddam's derived Lean library states `omega(F) ≤ 9/4` for every field, preserving the upstream division-free arithmetic model. It changes characteristic-sensitive separation/interpolation and descends finite-extension coefficients with a fixed overhead. These are field-scope contributions, not a strict exponent improvement. The README reports a 2026-10-07 build, axiom check, and default-kernel comparator replay at historical commit `c130a996c754b8407d92a4518db9711f4105260d`. It discloses a prebuilt solution, reduced sandbox capabilities, and no independent second kernel. The comparator target is the final exponent theorem; other corollaries have a different check scope. That historical report is not our replay of observed head `615b591…`. [Pinned README and verification record](https://github.com/jzuiddam/omega-nine-quarters-all-fields/blob/615b591cddd8792173c17b58558ef3b9f11a702c/README.md).

**selanavot/matrix-multiplication-all-fields.** Sela Navot's focused source fork also states `omega(F) ≤ 9/4` for arbitrary fields. It exposes both arithmetic-program and exact coefficient-rank conclusions, an important distinction over finite fields. Its proof description uses characteristic-safe separation, distinct interpolation nodes, and fixed-dimensional algebra descent. It explicitly does not supply practical constants or an effective uniform program generator. The source-fork purpose is field generalization, not reducing 9/4. [Pinned README](https://github.com/selanavot/matrix-multiplication-all-fields/blob/08481ef22bca7dc9ffba091083b7c1e81e537220/README.md).

Its release record reports Palomar mechanical verification on 2026-10-07 for `8375e73ed454e3128500d10d87480c5dd597ff03`, and associates version 1.0.0 with release commit `c88bb830aeb6ebd83f1e48a7bdae566ff5e0924d` and version DOI `10.5281/zenodo.23219128`. It describes six comparator claims and kernel evidence. This audit read the release record, not the full archived mechanical report or kernel receipts, and did not rerun them. The release record's pending-review statement is dated October 7; it does not establish current review or registration status. [Pinned release record](https://github.com/selanavot/matrix-multiplication-all-fields/blob/08481ef22bca7dc9ffba091083b7c1e81e537220/docs/releases/v1.0.0.md).

## Research implications and finite-certificate tasks

The following are project proposals and mathematical deductions from the certificate model, not discoveries attributed to these repositories.

1. **Build a small independent exact certificate checker first.** A certificate must specify dimensions, coefficient domain, ordered input/output bases, and all `U,V,W` factors. Check every coefficient of the bilinear map, including zero coordinates. Normalize transpose conventions. Record source revision, artifact digest, verification command, and result. Include deliberately corrupted factors and a characteristic-mismatch example as negative controls. Begin with a known seven-product identity so a baseline success cannot be confused with a new rank result.

2. **Make domain changes explicit.** An integer identity can be reduced into any field; a rational identity requires invertible denominators in the target characteristic. An F2 identity alone does not lift to characteristic zero. Number-field certificates need an exact algebra description and a valid interpretation in the target field. A low floating residual is only a candidate. A failed bounded search is not a lower bound.

3. **Attach an exponent gate to every direct-rank target.** For a square `u×u` scheme over the intended field, with `u ≥ 2` and `r` exact bilinear products, recursive use gives the standard arithmetic upper bound from `log_u(r)` (with the linear-combination costs accounted for). A sufficient strict-improvement gate is the integer test `r^4 < u^9`. Existing small-rank successes well above this gate remain tooling or finite-format results. Check available lower bounds before spending search effort on a small, impossible target.

4. **Require an explicit reduction for rectangular claims.** One route tensors the three cyclic permutations of an `(a,b,c)` scheme to obtain a square scheme of dimension `abc` and at most `r^3` products. Under that route the strict gate is `r^4 < (abc)^3`; report the construction and field assumptions, not just a table column labeled omega. More powerful asymptotic reductions need their own complete proof and overhead accounting.

5. **Use local search to produce auditable ingredients.** Rank-preserving flips, restricted-coefficient SAT neighborhoods, exact lifting attempts, and recombination can generate candidate factors. Retain the transformation path and exact result. An addition reduction or a new representation of the same rank is a separate outcome. For a public project, implement or reuse only components whose licenses and artifact provenance are resolved.

6. **Connect finite constructions to the theorem bottleneck.** A sector restriction, degeneration, or weight assignment should carry a finite exact support/identity certificate. Its route to a uniform spectral inequality, compatible growing family, or asymptotic rank bound must be stated separately. Constant-factor improvements in a linear-size separation period disappear after exponent normalization; they do not alone lower 9/4. Likewise, field descent preserves the starting exponent when its overhead is fixed before taking powers. Strict improvement needs a quantitatively stronger asymptotic step or a direct certificate crossing the rank gate.

The most useful initial combination is an independent verifier plus a provenance-aware certificate corpus, followed by narrowly scoped searches whose output has a declared asymptotic transfer target. A fresh global omega-record claim is not supported by this repository audit.
